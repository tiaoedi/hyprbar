Firefox is themed through the [Pywalfox](https://addons.mozilla.org/en-US/firefox/addon/pywalfox/) browser extension.
The **`pywalfox`** community template writes a pywal-compatible `colors.json` and uses Hyprbar's built-in
`firefox-theme` host to update the extension. No separate Python package or daemon is required.

## Requirements

- Hyprbar with the built-in `firefox-theme` post-action
- Community template **`pywalfox`**
- The [Pywalfox](https://addons.mozilla.org/en-US/firefox/addon/pywalfox/) extension

## Setup

1. **Install the Pywalfox extension** from [Firefox Add-ons](https://addons.mozilla.org/en-US/firefox/addon/pywalfox/).

2. **Enable the community template in Hyprbar:**
   - Open **Settings → Templates** (community templates)
   - Open **Browse Templates** and enable **`pywalfox`**

3. **Apply a theme** (change wallpaper / palette, or re-apply templates) so Hyprbar writes `colors.json` and runs
   `firefox-theme`. That installs the user-local native messaging manifest when needed:
   `~/.mozilla/native-messaging-hosts/pywalfox.json` → your `hyprbar` binary.
   Hyprbar-managed manifests are refreshed automatically when the executable path changes, including across NixOS
   store generations. Manifests installed by other Pywalfox hosts are left untouched.

4. **Restart Firefox** once after the manifest is first installed so it picks up the host.

After that, palette and dark/light mode changes should update the browser without a separate daemon package.

Multiple open Firefox profiles are supported with the built-in host: each profile runs its own native-messaging
process, and theme pushes fan out to all of them.

### Manual helpers

```bash
hyprbar firefox-theme install    # write the native messaging manifest
hyprbar firefox-theme update     # push colors to all running profile hosts
hyprbar firefox-theme uninstall  # remove the hyprbar-owned manifest
hyprbar firefox-theme --help
```

### Migrating from the legacy Python integration

1. Uninstall the legacy `python-pywalfox` package if it is no longer needed.
2. If `~/.mozilla/native-messaging-hosts/pywalfox.json` still points at the Python host, remove that manifest
   (or uninstall the Python package's host); Hyprbar **will not overwrite** a foreign host.
3. Enable **`pywalfox`**, re-apply templates (or change theme), then **restart Firefox**.

## Troubleshooting

- **Template not listed:** Community templates come from `https://api.noctalia.dev/templates`. Refresh / reopen
  Settings after the catalog publishes the entry. Offline mode blocks catalog downloads.
- **Extension not connecting:** Confirm the extension is enabled, the manifest exists under
  `~/.mozilla/native-messaging-hosts/pywalfox.json`, and Firefox was restarted after install.
- **Colors file updates but Firefox does not:** Confirm **`pywalfox`** is enabled and that the manifest `path` points
  to Hyprbar rather than the legacy Python host.
- **Only one of several Firefox profiles refreshes:** Restart each profile once after updating Hyprbar so every
  profile is running the new host; then theme pushes should reach all open profiles.
- **Stuck on the Python host after migrating:** Check the `path` field in the manifest; remove a foreign host entry
  before Hyprbar can install its own.
