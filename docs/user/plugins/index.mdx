Plugins extend Hyprbar with **bar widgets**, **desktop widgets**, **shell panels**, **control-center shortcuts**,
**launcher providers**, and headless **background services** - all driven by trusted [Luau](https://luau.org) scripts
running in isolated VMs. A plugin is a directory containing a static
`plugin.toml` manifest and one or more `.luau` entry scripts.

Plugins come from **sources**. This build currently references two externally maintained git sources; they are not Hyprbar-owned catalogs:

- **official** - `https://github.com/noctalia-dev/official-plugins` (externally maintained)
- **community** - `https://github.com/noctalia-dev/community-plugins` (community-maintained)

You can also add your own git repos or local directories.

## Enabling a plugin

Nothing is active until you enable it - installed ≠ enabled. Enabling a plugin from a git source exports just that
plugin's directory from the source repo cache into `$XDG_STATE_HOME/hyprbar/plugins/materialized/`. Hyprbar owns both
the repo cache and exported runtime files.

### From the settings GUI

Open **Settings → Plugins**. Use **Add source** to add a git repo or local directory. Each configured source is listed
with **Update** where applicable and **Remove** for custom sources, and every discovered plugin has an **enable toggle**.
Toggle a plugin on to fetch + activate it; toggle off to deactivate it. Incompatible plugins (see
[Compatibility](#compatibility)) are shown but cannot be enabled.

Plugins that expose **plugin-level settings** show a **gear** on their row - open it to configure options shared across
all of the plugin's parts (for example the screen recorder's codec, quality, and output folder). Settings persist to the
state dir, so a read-only config directory is fine. Bar-widget entries can also declare widget settings, edited where
that widget is configured.

If a plugin is enabled in `config.toml` and you disable it in Settings, Hyprbar writes an app-owned
`[plugins].enabled` override to `settings.toml`. That override wins until you remove or edit it.

### From the command line

```sh
hyprbar msg plugins list                              # every plugin across all sources, with enabled state
hyprbar msg plugins enable noctalia/screen_recorder  # legacy plugin ID; fetch (if needed) + enable
hyprbar msg plugins disable noctalia/screen_recorder # disable; code + settings are retained
hyprbar msg plugins update official                   # update a source, then hot-reload its plugins
```

Manage sources too:

```sh
hyprbar msg plugins source list
hyprbar msg plugins source add my-repo git https://github.com/me/my-plugins
hyprbar msg plugins source add my-dev path ~/dev/my-plugins
hyprbar msg plugins source remove my-repo
```

The configured `official` and `community` sources can be updated and enabled or disabled in Settings, but cannot be removed there or through IPC. Custom git/path sources are removable. **Auto-update plugins** is a dropdown for the global `[plugins].auto_update` mode: **All sources** (default), **official source only**, or **None**.

Enabling a plugin makes its entries available. Its **bar widget** then shows up in the Add-widget picker - add a widget
instance just like any built-in widget (or configure one by hand with `type = "<author>/<plugin>:<entry>"`). A
**control-center shortcut** is added from the control-center shortcuts settings, like any other shortcut. A **panel**
opens with `hyprbar msg panel-toggle <author>/<plugin>:<entry>` (or from a bar widget that runs the same command).
Panel **placement** (attached/floating, screen position, open-near-click) is configured per panel entry under
**Settings → Plugins**, same as built-in shell panels.

## Configuration

Plugin state lives under `[plugins]`. The `enabled` list and the sources are user intent (declarative-friendly); the app
also writes runtime toggles to its state file, and both are merged.

```toml
[plugins]
# Fully-qualified ids ("<author>/<plugin>") that are active.
enabled = ["noctalia/screen_recorder"] # legacy plugin ID retained for compatibility
auto_update = "all" # "all" | "official" | "none"; background git updates on startup and every 6 hours

# A git source: cached and updated by Hyprbar.
[[plugins.source]]
name     = "official"
kind     = "git"
location = "https://github.com/noctalia-dev/official-plugins"
enabled  = true

# A path source: an immutable local directory Hyprbar treats read-only
# (no git ops). Ideal for local development or Nix-managed plugins.
[[plugins.source]]
name     = "my-dev"
kind     = "path"
location = "~/dev/my-plugins"
enabled  = true
```

`auto_update` accepts one of:

- `"all"` (default) - update every enabled git source on startup and every 6 hours
- `"official"` - update only the built-in `official` source if enabled (matched by name **and** location, so a custom source reusing the name isn't trusted)
- `"none"` - never auto-update

The boolean form (`auto_update = true` / `false`) from earlier builds is no longer accepted - use `"all"` or `"none"`.
`enabled = false` on a source prevents it from being scanned or updated while retaining its app-managed clone.

Plugins placed by hand under `~/.local/share/hyprbar/plugins/<plugin>/` are discovered as a built-in **local** source -
handy for development. Like every plugin, they must be enabled before they activate. See
[File locations](/hyprbar/configuration/#file-locations) for where plugin code and everything else lives.

Git source operations are non-interactive. Private repos must be reachable through an already-working credential helper,
SSH agent, or SSH config; otherwise clone/update fails and Hyprbar continues without prompting for a password.
Git source runtime files are exported caches, not editable plugin state. Use a `path` source or
`~/.local/share/hyprbar/plugins/` for local plugin development.

A source `name` is its identity, so duplicate names in `[[plugins.source]]` are rejected with a config error. Replacing
a git source with the same name but a different `location` deletes Hyprbar's app-managed repo cache and exported
runtime files for that source, then re-fetches from the new location when needed.

## Updating

`hyprbar msg plugins update <source>` updates the source and hot-reloads its enabled plugins. The global
`[plugins].auto_update` mode decides what the background tick (startup + every 6 hours) updates: `"all"` (default)
pulls every enabled git source, `"official"` pulls only the configured `official` source, and `"none"` disables
background updates.
Updates are safe per enabled plugin: if one enabled plugin's new
version targets an unsupported plugin API level, Hyprbar keeps that plugin's previous exported copy, still updates
compatible enabled plugins from the same source, and advances the source catalog. After Hyprbar gains support for that
API level, the held plugin can catch up from the already-updated source revision.

## Compatibility

Every plugin declares a mandatory integer `plugin_api` in its manifest. It is the oldest Hyprbar plugin API level that
the plugin requires, independent of both the plugin's version and Hyprbar's release version. Hyprbar supports
plugin API levels <PluginApiRange />. Plugins outside the API range supported by the running shell are shown but badged
**"incompatible plugin API"** and cannot be enabled.

## Writing your own

Want to build a plugin? See **[Plugin Development](/hyprbar/plugins/development/)**. Hyprbar has no separate public plugin
store; the inherited community source is maintained at
[community-plugins](https://github.com/noctalia-dev/community-plugins), whose policies govern submissions there.
