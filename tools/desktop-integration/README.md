# Hyprbar desktop integration

These are the source files for the optional user-level integrations tested with
Hyprbar. They are not enabled automatically by building or installing the shell.
No browser profiles, personal GTK/Qt configurations, cookies, credentials or
machine-local backup files are included.

## Browser colors (Chrome and Brave)

`browser/chrome-theme-restart.py` is the shared Chromium core;
`browser/brave-theme-restart.py` configures its Brave paths. The supplied defaults
match native Fedora packages, not Flatpak/Snap. Review environment overrides and
actual profiles/executables before enabling the hooks elsewhere.

The template `browser/manifest.json.in` generates a theme extension manifest.
Copy it to the Hyprbar config directory as `templates/chrome/manifest.json.in`
and merge `browser/chrome-theme.toml`. Load the generated unpacked theme from
`~/.local/share/hyprbar/themes/chrome` through each intended browser profile's
supported extension UI. Generated files alone do not install or activate it.

Copy the two Python scripts to the config directory's `hooks/` directory. Merge
these entries into the **existing** `hooks.colors_changed` array, preserving any
other hooks:

```toml
[hooks]
colors_changed = [
  'python3 "$HOME/.config/hyprbar/hooks/chrome-theme-restart.py"',
  'python3 "$HOME/.config/hyprbar/hooks/brave-theme-restart.py"',
]
```

The example assumes the standard config directory; adapt it if an XDG or Hyprbar
config-home override is used. Do not blindly replace a working hook array.

The core hashes the manifest, verifies the theme is active, and restarts only a
matching browser whose generated palette changed. This **closes the browser**,
then requests session restoration. Save forms and other unsaved work before use.
It does not launch a closed browser merely for a palette change. It removes only
`Cached Theme.pak` in the generated theme directory after shutdown, or while the
browser is closed, so Chromium rebuilds the colors instead of reusing its old
compiled package. Cookies, browsing cache and profile data are not deleted.
A shutdown timeout or failed cache invalidation is not acknowledged as success.

The shell fix keeps `colors_changed` after asynchronous template rendering and
also requests the notification for an app-facing dark/light-mode change.
Registering a browser restart under `theme_mode_changed` instead would race the
rendering operation. No privileged debugger, public debugging port or separate
browser profile is required by this restart-based path.

A dynamic New Tab replacement is packaged separately in
[`../browser-newtab`](../browser-newtab/README.md). It changes only the New Tab
page and uses the existing search provider; it does not style websites.

## GTK4: Nautilus and Loupe

`gtk/nautilus-hyprbar.css` and `gtk/loupe-hyprbar.css` bridge legacy Orchis colors
to named colors already generated by Hyprbar's GTK4 template. Copy the selected
bridge to `~/.config/gtk-4.0/` and import it **after** the existing Hyprbar color
import in the user stylesheet. Discover and preserve existing theme symlinks,
back up their targets, and do not duplicate the palette import.

Example import, with the user's real absolute home path substituted:

```css
@import url("hyprbar.css");
@import url("file:///ABSOLUTE/HOME/.config/gtk-4.0/nautilus-hyprbar.css");
@import url("file:///ABSOLUTE/HOME/.config/gtk-4.0/loupe-hyprbar.css");
```

The Nautilus bridge was verified with Nautilus 50.4, GTK4 4.22, libadwaita 1.9
and Orchis-Purple-Dark-Compact. It changes colors, not icons or layout. The Loupe
bridge was verified with Loupe 50.0. Its image canvas uses its own adaptive neutral
background and is **not** changed by this CSS. Header, properties and overlay
controls are the intended themed surfaces; image pixels, transparency and color
management are untouched. Older/different app structures or themes may need
selector review. Already-open apps may need to reload or reopen their styles.

## Font and icons

- [`../hyprbar-font`](../hyprbar-font/README.md) builds the renamed OFL font
  derivative; ready-to-use files, provenance and license are under
  [`../../assets/fonts/Hyprbar`](../../assets/fonts/Hyprbar/README.md).
- [`../hyprbar-icons`](../hyprbar-icons/README.md) contains the original rounded
  icon theme, generator, tests and preview. Uncovered icons inherit Linux themes;
  no Apple artwork is included.

## Verification

Run from the repository root. Tests use temporary files and do not restart real
browsers or modify desktop settings:

```sh
python3 tools/desktop-integration/browser/test_chrome_theme_restart.py -v
python3 -m unittest discover -s tools/browser-newtab/tests -v
/usr/bin/python3 -m unittest discover -s tools/hyprbar-icons -v
```

`--dry-run` on either installed browser hook reports its decision without
restarting a browser or updating the saved digest. It can create its state
directory and lock, so use an isolated state-directory override for read-only
audits of live installations. Full browser New Tab tests use disposable profiles
and are documented in that tool's README. Native shell regression tests include
`template_apply_notify`, which checks that rendered output is present when the
color notification is delivered.
